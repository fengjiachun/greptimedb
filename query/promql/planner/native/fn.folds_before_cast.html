fn folds_before_cast(statement: &Expr, field_type: &DataType) -> bool
Expand description

Whether statement folds raw samples into an answer that is not a float, which is what makes the cast above it late.

An arithmetic operator’s cast_float makes its column a Float64, but a column type is not an answer: where an operand folds the samples before the cast reaches them, the existing plan folds exactly - sum of an Int64 column adds integers and casts the sum - while the raw series scan casts every sample and only then folds. Two integers above 2^53 that cancel answer 1 before the cast and 0 after it, so sum(integer_field) * 1 keeps the existing plan. sum(rate(m[5m])) is what that bound admits: the fold it applies is already a float fold, which is publishes_float_values of the aggregate itself.

A bare selector, a literal and a call hand over one sample at a time, so the cast reaches the same sample the scan casts and no fold happens in between.
